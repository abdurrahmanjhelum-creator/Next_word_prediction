# Next Word Predictor

This repository contains a single Python script that implements a simple next-word prediction model and a Tkinter GUI for interactive usage.



## What is included

- `next_word_prediction.py` — main script. It contains:
  - `NextWordPredictor`: a lightweight model that stores:
    - `first_words` (probabilities for sentence-start words),
    - `second_words` (probabilities for what follows a single word), and
    - `transitions` (probabilities for what follows a two-word context).
  - `get_extended_training_data()`: an in-script sample dataset used for training.
  - `train_on_sample_text()`: helper that trains the predictor on the sample data (and some additional names) and saves the model to `word_prediction_model.json`.
  - `NextWordPredictorUI`: a Tkinter-based GUI that starts the training (by calling `train_on_sample_text()`), shows suggestions, and lets you accept or insert predictions.
  - `interactive_demo()` / `if __name__ == "__main__"`: entry point that launches the GUI.

## Requirements

- Python 3.8+ (tested with Python 3.8+)
- Tkinter (usually included with Python; on some Linux distributions you may need to install it separately — see Troubleshooting)

No external ML libraries are required — the model is implemented using plain Python and JSON for persistence.

## Quickstart

1. Clone the repository:

```bash
git clone https://github.com/abdurrahmanjhelum-creator/Next_word_pridiction.git
cd Next_word_pridiction
```

2. Run the app:

```bash
python next_word_prediction.py
```

When you run it the first time the script will train on the built-in dataset (this happens at startup) and save the model to `word_prediction_model.json` in the current working directory.

## Behavior and usage notes

- The UI trains the model on startup (using `train_on_sample_text()`), which may take a few seconds depending on your machine.
- After training the model is saved as `word_prediction_model.json`.
- The GUI displays up to 5 suggestions for the next word. You can:
  - Click a suggestion to insert it (it replaces the last word or appends it depending on the current input),
  - Press Enter to accept the top suggestion,
  - Use keys 1–5 to select a suggestion while it is displayed.
- Predictions are generated by `NextWordPredictor.predict_next_word(text)` and returned as a list of `(word, probability)` tuples.

## How to customize training data

The script currently uses `get_extended_training_data()` (a string inside the file). To train on your own corpus:

- Option A — quick edit: open `next_word_prediction.py` and replace or extend the text returned by `get_extended_training_data()`.

- Option B — programmatic training and saving (example):

```python
from next_word_prediction import NextWordPredictor

predictor = NextWordPredictor()
with open('my_corpus.txt', 'r', encoding='utf-8') as f:
    text = f.read()
predictor.train(text)
predictor.save_model('word_prediction_model.json')
```

You can then modify `NextWordPredictorUI` to call `NextWordPredictor(model_path='word_prediction_model.json')` instead of retraining on startup.

## Loading an existing model instead of retraining

The `NextWordPredictor` constructor accepts `model_path`. If you want the app to load a previously saved model (and avoid retraining every run), change the UI initialization in the script to load the file if it exists, e.g.:

```python
# inside NextWordPredictorUI.__init__ replace train_on_sample_text() usage
if os.path.exists('word_prediction_model.json'):
    self.predictor = NextWordPredictor(model_path='word_prediction_model.json')
else:
    self.predictor = train_on_sample_text()
```

This small change will load the saved JSON model when available and fall back to training only if the JSON file is missing.

## File(s) created by the script

- `word_prediction_model.json` — JSON dump of the trained model. Note: the `transitions` keys are serialized as comma-separated strings (e.g., "word1,word2") and converted back into tuples when loaded.

## Troubleshooting

- If you get an ImportError for `tkinter` on Linux, install the system package for your Python version. For example on Debian/Ubuntu:

```bash
sudo apt-get install python3-tk
```

- If the GUI seems slow at startup, it's because the script trains on the internal dataset; save the trained model and use the load pattern above to avoid retraining.

- If you want better prediction quality, consider replacing the toy approach with a more robust tokenizer, more training data, or using pre-trained language models (outside the scope of this repo's current implementation).

## Development notes and suggestions

- The model is intentionally simple (frequency counts → probabilities). It is suitable for experimentation and learning but not production-quality language modeling.
- Suggested improvements:
  - Use a proper tokenizer (split on punctuation, lowercasing consistently, handle contractions),
  - Persist and reuse the tokenizer/vocabulary,
  - Make training incremental (append or fine-tune on new data) without retraining from scratch,
  - Add a CLI to train from files and to evaluate perplexity/top-k accuracy on a hold-out set,
  - Add unit tests for the predictor logic.
